Система заметок.

---

• Аккаунты (токены, почта).

• Черновики (корзина, отсутствие корзины минус один балл).

• Перетаскивание файлов (система Drag and Drop).

• Панель администратора.

• У заметок должны быть даты создания, изменения.

• Дизайн должен быть удобным, интерактивным, приятным (UI/UX).

• У фронтенда не должно быть отпечатков нейронки, минус два балла.

• Нейронка не должна ощущаться, без чувственная работа минус много баллов, нужен необычный, свой, продуманный и красивый дизайн.

• Все неработающие кнопки, функции будут минус балл, все должно работать.

• Адаптивка под телефоны, различные экраны.

• Обязательна проверка на бекенде, чтобы не заходили лишние данные на БД.

• Валидация.

• Полный цикл работы с заметками GRUD: редактирование, обновление, создание, удаление.

• У фронта и бека обдуманный пул стек используемых технологий, нужно будет развернуто рассказать зачем, почему и как так использовали.

• Презентация по стандартам колледжа, каждый делает свои слайды и презентует их, рассказывает.

• Гит контроль версий, общий репозиторий, мердж и код ревью.

• Тестировка должна быть многоуровневая и многослойная, тестируя все этапы и функционал сайта.

• БД реализует интеграцию.

• Развертывание на локальном сервере.

• Опционально иметь макет.

---

• Шаблоны для фронтенда: HTML-файлы, Thymeleaf создаются в папке src/main/resources/templates, один файл index уже создал.

• Для бекенда реализуем все слои бека: controller, service, model, repository.

• Как пример, взять уже готовый репозиторий по Арине: https://github.com/UltraKostik/UltraKostik_SpringBoot

• В репозитории уже есть структура проекта, модель, зависимости, а также добавлены Thymeleaf-шаблоны для списка товаров и формы.

---

• Ресурс в целом должен выглядеть как единое, аккуратное и цельное веб-приложение с продуманной навигацией.

• Структура страниц: главная, авторизация и регистрация, список заметок, страница отдельной заметки, черновики, корзина, панель администратора.

• Единый визуальный стиль на всех страницах: общая цветовая схема, типографика, отступы, скругления, состояния кнопок и полей ввода.

• Интерфейс должен быть интуитивно понятным: пользователь без подсказок понимает, куда нажать и что произойдет.

• Все состояния должны быть проработаны: загрузка, пустой список, ошибка, успешное действие, подтверждение удаления.

• Уведомления и обратная связь для пользователя: сообщения об успехе, ошибках, предупреждениях.

• Код должен соответствовать стандартам: читаемость, понятные имена переменных и методов, единый стиль форматирования, отсутствие мертвого кода.

• Разделение ответственности: фронтенд не содержит бизнес-логики, бэкенд не занимается представлением.

• Безопасность: хеширование паролей, защита от SQL-инъекций, проверка прав доступа, защита эндпоинтов.

• Работа с ошибками: централизованная обработка исключений на бекенде, корректные коды ответов.

• Логирование ключевых действий и ошибок на сервере.

• Документация: описание проекта, инструкция по запуску, описание структуры и эндпоинтов.

• Соответствие стандартам колледжа по оформлению, структуре проекта и презентации.
